# Fundamentos: conexión con n8n

## Versión

2

En Campos ancla, **tu software es el cerebro** (guarda los flujos, las reglas, las anclas y el estado de cada corrida) y **n8n es solo un puente** para hablar con herramientas externas (WhatsApp, Gmail, Google Calendar, Stripe, Playwright…). Nunca se programan reglas de negocio dentro de n8n.

## 1. Tu software llama a n8n (Ejecutor `integracion`)

Se usa cuando un paso de un flujo necesita que n8n ejecute una acción externa (por ejemplo, enviar un WhatsApp o crear una cita).

### A) Cómo se configura en Campos ancla
1. **Crear el ejecutor en `/v1/ejecutores`:**
   ```json
   {
     "id": "n8n-whatsapp",
     "nombre": "n8n — Enviar WhatsApp",
     "tipo": "integracion",
     "config": {
       "proveedor": "n8n",
       "url": "https://tu-n8n.com/webhook/enviar-whatsapp",
       "metodo": "POST",
       "secret": "N8N_WEBHOOK_TOKEN",
       "asincrono": false,
       "workflow_id": "14",
       "workflow_nombre": "Enviar WhatsApp",
       "editor_url": "https://tu-n8n.com/workflow/14"
     },
     "timeout_s": 30,
     "reintentos": 2,
     "espera_reintento_s": 10,
     "activo": true
   }
   ```
2. **Enlace al workflow en n8n (opcional):** en `config` puedes guardar `editor_url` (URL del editor), `workflow_id` y `workflow_nombre`. Si hay `editor_url` o `workflow_id` y no mandas `proveedor`, se asume `"n8n"`. En la ficha del Ejecutor (Resumen) aparece el botón **Abrir workflow en n8n ↗** y se muestran id/nombre si existen.
3. **Selector automático (opcional):** si el Worker tiene secrets `N8N_BASE_URL` y `N8N_API_KEY`, `GET /v1/integraciones/n8n/workflows` lista los workflows (`id`, `nombre`, `activo`, `editor_url`, `webhook_url` desde el nodo Webhook). Sin secrets responde `configured: false` + `hint`. En el formulario de Ejecutor `integracion`, si `configured: true`, el desplegable **Elegir workflow de n8n** rellena `url` / `editor_url` / `workflow_id` / `workflow_nombre`.
4. **Asignarlo a la skill:** en la skill correspondiente (por ejemplo, `avisar-cliente`), pon `"ejecutorId": "n8n-whatsapp"`.

### B) Los dos modos: síncrono (`asincrono: false`) vs. asíncrono (`asincrono: true`)

| Modo | Cuándo usarlo | Cómo funciona paso a paso |
|---|---|---|
| **Síncrono** (`"asincrono": false`) | Tareas rápidas (< 30 s): enviar un WhatsApp, un email o crear una fila. | 1. Tu API hace `POST` al nodo **Webhook** de n8n con `corrida_id`, `nodo_id`, `negocio`, `skill` y `entradas`.<br>2. El flujo de n8n termina con un nodo **Respond to Webhook** devolviendo un JSON con las anclas de salida (`{ "valores": { "_aviso.enviado_": true } }`).<br>3. Tu API guarda esas salidas en Mongo y avanza la corrida al siguiente paso inmediatamente. |
| **Asíncrono** (`"asincrono": true`) | Tareas largas (> 30 s): navegar una web con Playwright, esperar respuesta o procesar archivos pesados. | 1. Tu API hace `POST` al Webhook de n8n y deja la corrida en estado `esperando_integracion` (con un `lease_hasta` según `timeout_s`).<br>2. n8n responde `200 OK` al instante para liberar la conexión y sigue trabajando por detrás.<br>3. Cuando n8n termina, usa un nodo **HTTP Request** para llamar a tu API en `POST /v1/ejecutar/:skill/salidas`. |

### C) Qué envía n8n al terminar en modo asíncrono (`POST /v1/ejecutar/:skill/salidas`)
En el último nodo **HTTP Request** de n8n:
- **Método y URL:** `POST https://campos-ancla-api.web-legal-es.workers.dev/v1/ejecutar/mapear-recorrido/salidas`
- **Cabeceras:**
  - `Authorization: Bearer inv_...` (la clave de agente creada en Ajustes → Agentes)
  - `Content-Type: application/json`
- **Body JSON:**
  ```json
  {
    "corrida_id": "c-79dfd87a73874b63",
    "nodo_id": "mapear",
    "negocio": "pelo-sur",
    "valores": {
      "_version.recorrido.llega_a_b_": true,
      "_version.recorrido.campos_": [
        { "nombre": "Teléfono", "selector": "#phone", "clase": "sensible" }
      ]
    }
  }
  ```
Al recibir este `POST`, tu API valida que las anclas estén permitidas en `salidas` de esa skill, las escribe en MongoDB y encola automáticamente el siguiente paso de la corrida.

## 2. n8n despierta a tu software (Disparador `webhook`)

Se usa cuando algo ocurre fuera (entra un WhatsApp de un cliente, se rellena un formulario web o entra un pago en Stripe) y quieres que arranque un flujo en Campos ancla.

### Paso a paso
1. **En Campos ancla:** dentro de la ficha del flujo → pestaña **Disparadores** → **+ Añadir disparador**, creas uno de tipo `webhook` (puedes usar el Redactor para su `pipeline` si quieres filtrar qué webhooks arrancan corrida y cuáles se ignoran).
2. **Copias la URL única del disparador:** tiene la forma:
   ```
   POST https://campos-ancla-api.web-legal-es.workers.dev/v1/disparar/:flujo/:token
   ```
3. **En n8n:** pones un nodo **HTTP Request** apuntando a esa URL (no necesita cabecera `Authorization` porque el propio `:token` de la URL autentica el disparador) y envías en el body los datos del suceso:
   ```json
   {
     "negocio": "pelo-sur",
     "cliente_telefono": "+34600111222",
     "mensaje": "Quiero reservar corte mañana a las 17:00"
   }
   ```
4. **Qué hace tu software al recibirlo:**
   - Guarda el suceso en la colección `eventos` (`tipo: "webhook"`, con el `body`).
   - Ejecuta el `pipeline` del disparador sobre ese evento.
   - Si pasa el filtro, crea la corrida y el motor interno empieza a ejecutar el primer paso.

## 3. n8n como trabajador por turnos (Ejecutor `agente_externo`)

Es el modo clásico de compatibilidad (cuando una skill tiene `"ejecutorId": "agente-reservas-pagweb"` o `null`). Aquí tu API no empuja el trabajo hacia n8n, sino que n8n pregunta periódicamente si hay algún paso pendiente para él:

1. **Preguntar qué toca hacer:**
   `GET https://campos-ancla-api.web-legal-es.workers.dev/v1/corridas/:id/siguiente`
   - Devuelve la `skill`, el `systemPrompt` y los valores actuales de las `entradas`.
2. **Hacer el trabajo y entregar las salidas:**
   `POST https://campos-ancla-api.web-legal-es.workers.dev/v1/ejecutar/:skill/salidas` con `corrida_id`, `nodo_id`, `negocio` y `valores`.

## Reglas de oro entre Campos ancla y n8n

1. **Cero lógica en n8n:** los `if`, las esperas, los reintentos y qué paso va después de cuál se definen en el **Flujo** y el **Disparador** de Campos ancla, nunca en ramas dentro de n8n.
2. **Todo pasa por anclas:** n8n solo recibe anclas de `entradas` y solo devuelve anclas declaradas en `salidas`. Si n8n intenta escribir un campo que no está en `salidas` de esa skill, la API lo rechaza con error `400`.
3. **Claves seguras:** la clave `inv_...` que usa n8n para llamar a `/salidas` se guarda en **Credentials** de n8n, y el `secret` de los webhooks de n8n se guarda en los **Secrets** del Worker de Cloudflare.
