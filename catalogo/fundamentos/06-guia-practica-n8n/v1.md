## Parte 1 · Los 3 modos de conectar n8n con Campos ancla

En Campos ancla, **el hub es el cerebro** (guarda los flujos, las decisiones, las esperas, las anclas y el estado de cada corrida) y **n8n es solo el brazo ejecutor** para hablar con servicios externos (WhatsApp, telefonía, Google Calendar, Gmail, Playwright, Stripe…). **Nunca se programan reglas de negocio ni condicionales de proceso dentro de n8n.**

Existen exactamente **3 formas de conectar n8n** según quién inicie la comunicación:

```
=====================================================================================
 MODO 1 · SALIDA: Campos ancla llama a n8n (Ejecutor tipo "integracion")
=====================================================================================
 [Motor de Campos ancla] ──POST al Webhook de n8n con entradas──► [Workflow en n8n]
    (paso de Corrida)    ◄──Devuelve salidas (directo o /salidas)─ (WhatsApp/API/etc.)

=====================================================================================
 MODO 2 · ENTRADA: n8n despierta a Campos ancla (Disparador tipo "webhook")
=====================================================================================
 [Suceso externo en n8n] ──POST /v1/disparar/:flujo/:token──► [Campos ancla]
 (WhatsApp/Llamada/Pago)   (hidrata _anclas_ del body solo)   (crea Evento + Corrida)

=====================================================================================
 MODO 3 · POR TURNOS (PULL): n8n pregunta qué trabajo hay (Ejecutor "agente_externo")
=====================================================================================
 [n8n con Cron / Loop] ──1. GET /v1/corridas/:id/siguiente────────► [Campos ancla]
                       ──2. POST /v1/ejecutar/:skill/salidas──────► (avanza Corrida)
```

---

### Modo 1 · Campos ancla llama a n8n (Ejecutor `integracion`)

Se utiliza cuando un paso de un Flujo necesita que n8n ejecute una acción externa (por ejemplo: enviar un WhatsApp, agendar una cita o lanzar un navegador Playwright).

#### A) Cómo se configura en Campos ancla
1. **Crear el Ejecutor (`POST /v1/ejecutores` o en `Catálogo → Ejecutores → + Añadir ejecutor`):**
   ```json
   {
     "id": "n8n-whatsapp",
     "nombre": "n8n — Enviar WhatsApp",
     "tipo": "integracion",
     "config": {
       "proveedor": "n8n",
       "url": "https://tu-n8n.com/webhook/enviar-whatsapp",
       "metodo": "POST",
       "secret": "N8N_WEBHOOK_TOKEN",
       "asincrono": false,
       "workflow_id": "14",
       "workflow_nombre": "Enviar WhatsApp",
       "editor_url": "https://tu-n8n.com/workflow/14"
     },
     "timeout_s": 30,
     "reintentos": 2,
     "espera_reintento_s": 10,
     "activo": true
   }
   ```
2. **Selector automático de workflows de n8n (opcional):**
   - Si el Worker tiene configurados los secrets `N8N_BASE_URL` y `N8N_API_KEY`, el endpoint `GET /v1/integraciones/n8n/workflows` devuelve automáticamente todos tus workflows de n8n con su `id`, `nombre`, `activo`, `editor_url` y `webhook_url` (extraído del nodo Webhook de n8n).
   - En el formulario del Ejecutor en el Panel UI, el desplegable **Elegir workflow de n8n** rellena de golpe `url`, `editor_url`, `workflow_id` y `workflow_nombre`, y en la ficha del Ejecutor aparece el botón directo **Abrir workflow en n8n ↗**.
3. **Asignar el Ejecutor a la Skill:** en la ficha de la Skill (`Catálogo → Skills`), pon `"ejecutorId": "n8n-whatsapp"`.

#### B) Qué payload JSON envía Campos ancla al Webhook de n8n
Cuando la corrida llega a esa skill, el motor hace `POST` a `config.url` con este cuerpo exacto:
```json
{
  "corrida_id": "c-92a52d221c8349ee",
  "nodo_id": "paso-n8n",
  "skill": "procesar-llamada-n8n",
  "negocio": "pelo-sur",
  "entradas": {
    "_cliente.nombre_": "Ana",
    "_cliente.telefono_": "+34600111222"
  },
  "salidas_esperadas": [
    "_llamada.cliente_id_",
    "_llamada.fecha_",
    "_llamada.resultado_"
  ]
}
```

#### C) Cuándo elegir Síncrono (`asincrono: false`) vs. Asíncrono (`asincrono: true`)

| Modo | Cuándo elegirlo | Cómo responde n8n |
|---|---|---|
| **Síncrono** (`"asincrono": false`) | Tareas rápidas (**< 30 segundos**): enviar un WhatsApp, mandar un email, crear un evento en Google Calendar. | El workflow de n8n termina con un nodo **Respond to Webhook** devolviendo HTTP `200` y un JSON con las anclas de salida:<br>`{ "valores": { "_llamada.cliente_id_": "cli-1", "_llamada.fecha_": "2026-10-26", "_llamada.resultado_": "cita" } }`<br>Campos ancla guarda las salidas en MongoDB y avanza al siguiente nodo en el acto. |
| **Asíncrono** (`"asincrono": true`, valor por defecto) | Tareas largas (**> 30 segundos**): navegar una web con Playwright, transcribir un audio largo o esperar un proceso pesado. | 1) El nodo Webhook de n8n responde `200 OK` de inmediato (*Respond: Immediately*) y la corrida queda en estado **`esperando_integracion`** (con bloqueo `lease_hasta` durante `timeout_s`).<br>2) Cuando n8n termina el trabajo pesado, su último nodo **HTTP Request** llama a `POST /v1/ejecutar/:skill/salidas`. |

#### D) Cómo entrega n8n las salidas en modo asíncrono (`POST /v1/ejecutar/:skill/salidas`)
En el último nodo **HTTP Request** de tu workflow en n8n:
- **Método y URL:** `POST https://campos-ancla-api.web-legal-es.workers.dev/v1/ejecutar/procesar-llamada-n8n/salidas`
- **Cabeceras:**
  - `Authorization: Bearer inv_TU_TOKEN_DE_AGENTE` *(creado en Ajustes → Agentes)*
  - `Content-Type: application/json`
- **Body JSON:**
  ```json
  {
    "corrida_id": "c-92a52d221c8349ee",
    "nodo_id": "paso-n8n",
    "negocio": "pelo-sur",
    "valores": {
      "_llamada.cliente_id_": "cli-1",
      "_llamada.fecha_": "2026-10-26T10:30:00.000Z",
      "_llamada.resultado_": "cita"
    }
  }
  ```

### Modo 2 · n8n despierta a Campos ancla (Disparador `webhook` + Hidratación automática)

Se utiliza cuando ocurre algo en el exterior (entra un mensaje de WhatsApp, termina una llamada telefónica en Vapi/Twilio o entra un formulario web) y quieres que arranque un Flujo en Campos ancla.

1. **En Campos ancla:** abre el Flujo → pestaña **Disparadores** → **+ Añadir disparador** → elige `tipo: "webhook"` y guarda.
2. **Copia la URL única generada:**
   `POST https://campos-ancla-api.web-legal-es.workers.dev/v1/disparar/:flujo/:token`
   *(No necesita cabecera `Authorization` porque el propio `:token` de 32 caracteres de la URL autentica el disparador).*
3. **Envía los datos desde n8n aprovechando la Hidratación Automática de Anclas:**
   - El motor de Eventos (`hidratarAnclasDesdeEvento`) busca automáticamente en el `body` (y en `body.valores` o `body.datos`) cualquier clave que coincida con:
     - El nombre canónico del ancla (`"_cliente.telefono_"`)
     - El `id` sin guiones (`"cliente.telefono"`)
     - La `claveMongo` (`"telefono"`)
     - Cualquiera de los `aliases[]` configurados en el ancla (ej. `"contacto.telefono"`)
   - Todo lo que coincida queda cargado directamente en `corrida.datos` para el primer paso del flujo:
     ```json
     {
       "negocio": "pelo-sur",
       "_cliente.nombre_": "Ana",
       "_cliente.telefono_": "+34600111222",
       "_llamada.duracion_s_": 45,
       "_llamada.intencion_": "reservar"
     }
     ```

### Modo 3 · n8n como trabajador por turnos (`Ejecutor agente_externo`)

Es el modo clásico de compatibilidad cuando n8n (o un script en un servidor externo) no tiene URL pública y prefiere preguntar periódicamente qué trabajo hay pendiente:
1. **Preguntar qué paso toca hacer:**
   `GET https://campos-ancla-api.web-legal-es.workers.dev/v1/corridas/:corridaId/siguiente`
   - Devuelve `{ ok: true, tipo: "skill", nodo_id, skill, systemPrompt, entradas, salidas_esperadas }`.
2. **Hacer el trabajo y entregar las salidas:**
   `POST https://campos-ancla-api.web-legal-es.workers.dev/v1/ejecutar/:skill/salidas` enviando `corrida_id`, `nodo_id`, `negocio` y `valores`.

## Parte 2 · Cómo crear un software nuevo desde cero en 8 pasos exactos

Si vas a montar un software nuevo en Campos ancla (por ejemplo, un sistema de **Facturación** o **Citas de Clínica**), sigue siempre este orden de abajo hacia arriba para que todas las piezas encajen a la primera:

| Paso | Qué objeto creas | Dónde en el Panel UI / API | Qué debes definir en este paso |
|---|---|---|---|
| **Paso 1** | **Cluster** *(o reusar `atlas-principal`)* | `Catálogo → Clusters` | Conectar la URI de MongoDB Atlas en la pestaña **Conexión** y pulsar **Probar**. |
| **Paso 2** | **Base de datos (Proyecto)** y sus **Colecciones** | `Catálogo → Base de datos → + Añadir` | Definir `id`, `baseDatos` (ej. `software_clinica`), `clusterId`, la lista de `colecciones[]` (indicando cuáles son `unico_por_negocio` y cuáles `multiple`) y las `relaciones[]` (`N:1`). |
| **Paso 3** | **Campos MongoDB** y **Campos ancla** | `Catálogo → Campos ancla → + Añadir` | Crear cada `_ancla_` indicando su `coleccion`, `claveMongo`, `tipo`, si es `obligatorio` y si es `sensible`. *(La API sincroniza sola su Campo MongoDB hermano).* |
| **Paso 4** | **Empujar esquema a Atlas** | `Catálogo → Base de datos → [Proyecto] → botón Empujar esquema` | Ejecuta `POST /v1/proyectos/:id/crear-bd` para que las colecciones y validadores `$jsonSchema` queden creados en MongoDB Atlas. |
| **Paso 5** | **System prompt** y **Ejecutores** | `Catálogo → System prompts` y `Catálogo → Ejecutores` | Crear el prompt base (si hay pasos con IA) y dar de alta los ejecutores de `integracion` (webhooks de n8n) o `modelo` que vayas a necesitar. |
| **Paso 6** | **Skills** | `Catálogo → Skills → + Añadir` | Crear cada tarea con su markdown, asignarle sus `entradas[]`, sus `salidas[]`, su `ejecutorId` y vincularla al Proyecto. Revisar la pestaña **Operativa → Huecos** del Proyecto para confirmar que ningún ancla de entrada se quedó huérfana. |
| **Paso 7** | **Flujo** | `Catálogo → Flujos → + Añadir` | Diseñar los `nodos[]` y `aristas[]` (puedes escribir la intención en el **Redactor**, pulsar **Generar** y luego **Guardar versión**). |
| **Paso 8** | **Disparadores** y **Prueba** | `Catálogo → Flujos → [Flujo] → Disparadores` | Añadir el disparador (`webhook`, `cambio_datos`, `horario` o `manual`), probar el filtro con **Probar** (dry-run) y lanzar la primera **Corrida**. |

## Parte 3 · Recetas prácticas de producción (listas para copiar)

### Receta 1 · Consultar datos en MongoDB sin gastar IA (`consultar-datos`) y lanzar subflujos en abanico (`sobre_ancla`)
**Caso de uso:** Quieres buscar todas las llamadas cuyo resultado fue `"no_contesto"` y lanzar un subflujo de rellamada para cada una (hasta 50 en paralelo).

1. **Al lanzar la corrida (o en un paso previo de `transformar-datos`), pasas en `datos_iniciales` la consulta para `consultar-datos`:**
   ```json
   {
     "_consulta.coleccion_": "llamadas",
     "_consulta.pipeline_": [
       { "$match": { "resultado": "no_contesto" } },
       { "$limit": 20 }
     ]
   }
   ```
2. **Definición del Flujo (`nodos` y `aristas`):**
   - El nodo `buscar` ejecuta la skill interna `consultar-datos` (coste `0`) y deja el array de documentos en `_consulta.resultado_` y la cantidad en `_consulta.total_`.
   - El nodo `hay-pendientes` (`decision`) comprueba con `"gt": ["_consulta.total_", 0]` si hay al menos 1 documento.
   - El nodo `lanzar-rellamadas` (`subflujo`) usa `"sobre_ancla": "_consulta.resultado_"` para crear una corrida hija por cada llamada encontrada:
   ```json
   {
     "nodos": [
       { "id": "inicio", "tipo": "inicio" },
       { "id": "buscar", "tipo": "skill", "skill": "consultar-datos" },
       {
         "id": "hay-pendientes",
         "tipo": "decision",
         "condicion": { "gt": ["_consulta.total_", 0] }
       },
       {
         "id": "lanzar-rellamadas",
         "tipo": "subflujo",
         "flujo_id": "llamadas-prueba-n8n",
         "sobre_ancla": "_consulta.resultado_"
       },
       { "id": "fin", "tipo": "fin" }
     ],
     "aristas": [
       { "desde": "inicio", "hacia": "buscar" },
       { "desde": "buscar", "hacia": "hay-pendientes" },
       { "desde": "hay-pendientes", "hacia": "lanzar-rellamadas", "cuando": true },
       { "desde": "hay-pendientes", "hacia": "fin", "cuando": false },
       { "desde": "lanzar-rellamadas", "hacia": "fin" }
     ]
   }
   ```

---

### Receta 2 · Transformar o calcular anclas en memoria sin IA (`transformar-datos`)
**Caso de uso:** Quieres fijar o renombrar valores de anclas dentro de `corrida.datos` (y persistirlos en MongoDB si son anclas del catálogo) con coste `0` y sin llamar a ningún modelo.

- Usa un nodo `skill` con `"skill": "transformar-datos"` y pásale en `_consulta.pipeline_` etapas `$addFields` o `$project`:
  ```json
  {
    "_consulta.pipeline_": [
      {
        "$addFields": {
          "_llamada.resultado_": "cita",
          "_cliente.nombre_copia_": "$_cliente.nombre_"
        }
      }
    ]
  }
  ```

### Receta 3 · Esperar X minutos/horas antes de continuar (`espera` con reloj + botón «Adelantar»)
**Caso de uso:** Después de registrar una llamada, quieres esperar **2 horas** antes de enviar una encuesta, pero pudiendo saltarte la espera durante las pruebas con el botón **Adelantar**.

```json
{
  "nodos": [
    { "id": "inicio", "tipo": "inicio" },
    { "id": "registrar", "tipo": "skill", "skill": "procesar-llamada-n8n" },
    { "id": "esperar-2h", "tipo": "espera", "horas": 2, "modo": "tiempo" },
    { "id": "fin", "tipo": "fin" }
  ],
  "aristas": [
    { "desde": "inicio", "hacia": "registrar" },
    { "desde": "registrar", "hacia": "esperar-2h" },
    { "desde": "esperar-2h", "hacia": "fin" }
  ]
}
```
- Al llegar a `esperar-2h`, la corrida se pone en `esperando_tiempo` y calcula `_despertar_en_`.
- En cualquier momento puedes abrir la ficha de la Corrida en el panel y pulsar **Adelantar** (`POST /v1/corridas/:id/aprobar`) para que salte inmediatamente a `fin`.

## Parte 4 · Guía rápida de diagnóstico cuando algo no ocurre como esperabas

| Síntoma observado | Dónde mirar en el Panel UI | Causa exacta y cómo solucionarlo |
|---|---|---|
| **Hice un cambio en Mongo o envié un webhook y NO se creó ninguna Corrida** | `Catálogo → Flujos → [Flujo] → Corridas → subpestaña Eventos` | Mira el array `resultado[]` del Evento:<br>• `motivo: "pausado"` → activa el disparador.<br>• `motivo: "anti_bucle"` → el cambio lo hizo una corrida del mismo flujo (comportamiento correcto para evitar bucle infinito).<br>• `motivo: "agrupado"` → ya saltó hace menos de `agrupar_segundos`.<br>• `motivo: "pipeline_vacio"` → el `$match` del pipeline no coincidió con el documento; usa el botón **Probar** del disparador para ajustar el filtro. |
| **n8n llama a `POST /v1/ejecutar/:skill/salidas` y recibe `HTTP 400`** | `Catálogo → Skills → [Skill] → Asociados → Anclas → Salidas` | Estás enviando en `valores` un ancla que **no está declarada en `salidas[]`** de esa skill (o olvidaste enviar `negocio`). Añade el ancla a `salidas[]` de la skill. |
| **Una Corrida lleva mucho tiempo en `esperando_integracion` y luego pasa a `fallida` con `error: "timeout"`** | `Catálogo → Flujos → [Flujo] → Corridas → [Corrida] → pestañas Pasos / Errores` | El ejecutor externo (`integracion` asíncrona o `agente_externo`) no llamó a `POST /v1/ejecutar/:skill/salidas` antes de que venciera `timeout_s` del ejecutor. Revisa el historial del workflow en n8n y pulsa **Reintentar** en la ficha de la Corrida. |
| **Una Corrida aparece en estado `atascada`** | `Catálogo → Flujos → [Flujo] → Corridas → [Corrida]` | Estuvo en `en_curso` más de 10 minutos sin bloqueo `lease_hasta` activo. Pulsa el botón **Reanudar** en la cabecera de la Corrida (`POST /v1/corridas/:id/reanudar`). |
| **Dos pasos seguidos de mi flujo sobrescriben el mismo documento en vez de crear uno por corrida (o viceversa)** | `Catálogo → Colecciones → [Colección]` | Revisa el `modo_escritura` de la colección en `proyecto.colecciones`:<br>• Usa `"unico_por_negocio"` para fichas maestras (1 por cliente, como `negocios`).<br>• Usa `"multiple"` para registros históricos (1 por corrida, como `llamadas` o `reservas`), que se agrupan dentro de la misma corrida mediante `corrida.datos._documentos_`. |
